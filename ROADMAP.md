# Roadmap

AgilaLogic develops in gated phases. Each phase must prove reliability before the next level of authority is enabled.

## Phase 1 — Foundation

- core architecture documentation
- deterministic cognitive modules
- Supabase state, queue, approvals, evidence, lessons
- read-only external sensors
- approval-gated reversible writes
- health monitoring

## Phase 2 — Practical daily use

- context-aware Gmail reply drafting
- richer Calendar preparation workflows
- Drive project-reference monitoring
- GitHub commit/issue/PR observation
- stronger observability and outcome tracking

## Phase 3 — Controlled engineering workflows

- approval-gated branch creation
- approval-gated file changes
- draft pull requests
- CI/status inspection
- rollback-aware change proposals

## Phase 4 — Bounded autonomy

Only after sufficient evidence:

- narrowly scoped reversible actions
- explicit domain delegation
- confidence thresholds tied to historical outcomes
- automatic rollback or stop conditions where feasible

## Non-goals

- unrestricted autonomous external actions
- silent privilege escalation
- opaque multi-agent behavior without traceability
- confidence inflation without evidence

## Success criterion

The system is successful when it improves judgment and execution quality while preserving truth, reversibility, traceability, and user authority.
